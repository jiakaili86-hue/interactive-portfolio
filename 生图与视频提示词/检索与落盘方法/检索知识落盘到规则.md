# 检索知识落盘到规则

## 何时必须落盘

在对话中使用了 **WebSearch / 网页检索**（或用户明确要求「上网学习」），且检索结论满足任一条件时，**同一次协作内**在交付用户答复之后或同时，**写入对应规则文件**：

- 结论会在 **后续多次** 同类任务中复用（提示词方法论、平台能力、防崩技巧、行业口径等）；
- 或用户明确要求 **「总结到规则里」「写进规则」**。

**不必落盘**：一次性事实（某日新闻、单次查询结果）、与项目规则无关的闲聊、用户禁止改文件的指令。

## 写到哪一份规则（主题映射）

| 主题域 | 优先落盘文件 |
|--------|----------------|
| 即梦 Seedream / Seedance、**参考生视频**与分镜、写实/国漫画风与提示词；电影化场景/情感表达 | **`.cursor/rules/jimeng-core-delivery.mdc`**（每次硬约束：全能参考默认、`@` 三层优先级、道具/场景/角色三视图默认、字幕禁令、Markdown 项目结构、镜头NN 规范、四段式模版、最终自检）；按口令触发的画风合集 **`.cursor/rules/jimeng-styles.mdc`**（A 超写实电影/A2 + B 2D 赛璐璐/C2 + C 搞笑彩绘极简 + D 手绘铅笔速写，四节互斥）；按需触发的工作流合集 **`.cursor/rules/jimeng-workflows.mdc`**（A 分镜图→视频/九宫格 + B 多段延长/硬切/资源复用 + C 手机自拍 POV + D 真人过审/一致性）；技法全文与方法论见 **`jimeng-video-prompt.mdc`**（万能公式、电影化技法、影视表现力技法库等） |
| 海豚短视频口播、纯净脚本、信息来源与改稿流程 | `sop/video_rules.md` |
| 网络检索的通用质量与条数归纳（与落盘的关系） | `.cursor/rules/web-search-quality.mdc`（仅增补交叉引用或总则，避免重复堆全文） |

若某条知识同时属于多域：**主落盘一处**（最常用路径），他处只加 **一句交叉引用** 指向主节标题。

## 怎么写（格式）

1. **提炼**：不粘贴长文；写成 **可操作清单、对照表、公式补行**；与已有章节去重后合并。  
2. **标注**：可在小节标题或段首加 **「外源共识」** 或 **「检索摘要·主题」**，必要时括号注明年份（如 2025–2026）。  
3. **位置**：优先插入 **现有最相关章节**（例如在「三视图模板」下增补「差异化」而非新建孤立文件）；避免无目录的长附录。  
4. **篇幅**：单次数条要点为宜；同一文件多次更新可叠短表，**不删除**仍有效的旧条，除非明确过时。  
5. **冲突**：新检索与旧规则矛盾时，在规则内 **简短说明以何为准**（如「产品以即梦当前版本为准」），或分列「社区说法」与「本项目采用」。

## 与 `web-search-quality.mdc` 的关系

- 检索过程仍遵守 **时效性、多源交叉、归纳条数** 等要求。  
- **落盘** 是对其中「融合进我们自己的规则和内容体系」的 **硬性落地**：归纳要点不仅出现在当次答复，还须进入上表映射的规则文件（除非该次纯属海豚纯净改稿等已由 `web-search-quality` 指定改具体脚本的流程）。

## 即梦类关键词的交付形式

产出 Seedream/Seedance 提示词时，除更新项目内 Markdown 外，**须在对话中给出分块的、可直接复制的完整正文**（与 `jimeng-video-prompt.mdc` 第三步「交付形式」一致），不得仅指向路径。**每次修改关键词后**，仍须在对话中再发一遍可复制正文（全文或变更段+余同前），见同文件「修订再交付」。

## 禁止

- 把整篇转载或营销软文贴进规则。  
- 为落盘而新建大量重复规则文件；优先 **增补现有 `.mdc` / `sop`**。  
- 在用户未要求且与任务无关时，修改与主题无关的规则文件。
