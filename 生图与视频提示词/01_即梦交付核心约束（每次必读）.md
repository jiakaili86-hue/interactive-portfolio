# 即梦交付核心约束（每次遵守）

> **本文件合并自旧 5 份规则**：`jimeng-delivery-standard.mdc`、`seedance-forbid-pure-text-video.mdc`、`jimeng-no-unasked-seedream-or-at.mdc`、`jimeng-props-on-request.mdc`、`jimeng-character-16-9-sheet.mdc`。  
> **配套**：技法全文见 **`jimeng-video-prompt.mdc`**；画风模版合集（超写实/赛璐璐/搞笑彩绘极简/铅笔速写）见 **`jimeng-styles.mdc`**；工作流合集（九宫格分镜/多段视频/自拍 POV/真人过审/导演流程图/场景四视图）见 **`jimeng-workflows.mdc`**；用户台词不可改的铁律见本文件 § 5.4。

> **强制复习**：每次产出视频关键词前，**必须先执行 `jimeng-video-prompt.mdc` 中「第零步：交付前强制复习」**——检查景别叙事目的、镜头角度情绪选择、构图法则、光线色彩叙事、对话镜头升级路径、180°/30°法则、人物出场模式等全部资料要点，确保已收集的方法论用到位而非浪费。

## 1. Seedance 视频默认路径：全能参考 + @

### 1.1 默认必走「全能参考生视频」

- 使用 **Seedance 2.0 全能参考生视频**（界面可能写作「参考生视频」「全能参考」，以即梦当前版为准）。
- **先**在即梦内 **上传/绑定** 参考图或（可选）短视频；**再**写提示词。
- 项目 Markdown 须有 **`## 4.5`（或等价）素材与 @ 映射**；每镜须有 **本镜须绑定**；**提示词代码块内**须出现 **`@图片N` / `@视频N`**，与映射表序号一致。
- **对话里**复述分镜时：同样要带 **绑定说明 + 含 `@` 的正文**，禁止只复读无 `@` 的纯描写。

### 1.2 「删除纯文生」的含义

**不是**删掉技法段落里「怎么写画面、运镜、情绪」的内容。

**是**从工作流里 **废除**下面这种 **默认交付**：

- 把 Seedance 当成 **纯文生**：只给一大段中文画面描写；
- **零参考**：不列要上传的图/视频、不出现 `@图片N` / `@视频N`；
- 却当作「可直接在即梦用的完整视频提示词」交给用户。

除非用户 **当次用原话** 明确说 **只要纯文、不要参考图、不要 @**，否则 **一律禁止** 上面这种交付。

### 1.3 `@` 使用的三层优先级（合并旧两份冲突规则）

| 层级 | 规则 |
|------|------|
| **默认（最常态）** | Seedance 视频提示词正文必须有 `@`（全能参考），且与上传顺序一致 |
| **用户原话例外** | 用户当次明确说「不要 @ / 不要参考 / 只要纯文」时，才允许零参考；此时正文不出现任何 `@图片N/@视频N` |
| **道具 `@` 不自动扩展** | 即使在默认全能参考下，**道具的 `@` 仍须用户明确要求**；未要求时道具只在句内文字描述，不写 `@道具图` 也不建道具映射表 |

### 1.4 快速自检（任一命中 = 违规）

| 情况 | 判定 |
|------|------|
| 用户未声明纯文生，但分镜提示词里 **没有任何 `@`** | 禁止 |
| 只给了「整段复制」代码块，但 **未说明要上传哪些素材、@ 序号怎么对** | 禁止 |
| 用「画面写全了就行」代替 **参考 + @** | 禁止 |
| 用户明确说不要 `@`，但仍写了 `@图片` / `@视频` / 映射表 | 禁止 |

## 2. 默认不主动出 Seedream（角色 / 道具 / 场景）

### 2.1 角色：默认仅单张 16:9 三视图总览

- **每个角色** 的 Seedream 产出：**仅一张** **16:9 横版** **三视图总览图**（同一画面内包含 **正视、侧视、后视** 与版式分区；本项目默认版式为 **左约 1/3 面部特写 + 右约 2/3 三视图并列**，详见 `jimeng-video-prompt.mdc`「三视图生图模板」）。
- **动画风格统一版式**：凡是动画类角色（2D 赛璐璐、3D 动画、皮克斯式、国漫 3D、卡通、彩绘、铅笔线稿等），不管具体画风如何，角色三视图一律使用 **左约 1/3 面部特写 + 右约 2/3 正面/侧面/背面全身三视图**。同一项目内所有动画角色必须使用同一版式、同一画风语言、同一渲染质感；禁止一个角色是带特写角色表，另一个角色变成纯三等分 turntable。
- **不要**默认再生成：额外单独头像图、单独全身图、第二套比例、线稿/上色拆两张、9:16 或 1:1 角色设定替代 16:9 总览等——**除非用户当次明确要求**。
- **超写实真人**的角色三视图版式有专门口径（三等分并排，无面部特写区），见 `jimeng-styles.mdc` → A 节「超写实实拍真人」。

### 2.2 道具：默认不出 Seedream，视频 prompt 内文字描述

- **简易道具**（普通箭矢、单刀、长矛、书本、茶杯、石块、简易盾牌）：**永远不出**单独参考图。在视频 prompt 中写清材质与颜色即可（如「深木色箭杆金色箭羽三角金属箭头」）。
- **复杂道具**（花纹繁复的神器、标志性定制武器、需多镜头严格同形的机械/法器、带固定 UI 的全息界面）：**默认仍不出**单独道具图。
- **唯一例外**：用户在同一次任务里 **用原话** 说「要给某某道具出参考图 / 要某某道具的 Seedream 关键词」并 **逐条列出道具名** 时，才为 **点名项** 撰写 Seedream 关键词。未点名一律不写。

### 2.3 场景：默认不出 Seedream，交给 Seedance 文字生成

- 场景默认 **不出** Seedream 文生图。环境、布景在 Seedance 视频提示词里用中文写清（光影、材质、纵深、时代感等）。
- 后续若要复用已生成场景，优先 `@` 前面已生成出该场景的视频来锁场景空间、光色、道具方位和画风连续性。
- **唯一例外**：用户当次明确说「给雪山出个场景图」「木屋场景单独生成一下」「四宫格场景总览图」「场景多视角图」「场景 360 总览」等，才出对应场景图。**例外触发时按 `jimeng-workflows.mdc § F` 模版生成（GPT Image 2 优先，Seedream 次选）；四视图角度文字写死、禁止人形剪影**。
- 用户已自备场景图时，**不要**再生成；改为上传 + `@图片N`。

### 2.4 例外的统一原则

- 用户必须 **当次用原话** 说明要出图，且 **逐条列出** 要出图的项。
- 即使触发例外，**也只写点名项**，不替用户「为了锁造型」扩张清单。
- 不确定要不要出某张图时：**先问用户**，禁止先写满再问，也禁止在交付正文里写「若…/可选/没有则…」类分支。

## 4. 分镜单元规范

每个分镜固定结构：

- **标题**：`### 镜头NN · 名称`（NN 为 **01、02** 两位数字）。
- **元数据顺序**（固定，不得打乱）：**建议时长** → **模型** → **本镜须绑定（@ 与素材）** → **台词** → **提示词（整段复制）**。
- **提示词代码块**：单独 fenced 代码块（建议语言 `text`），**围栏单独成行**；正文内须含与 `## 4.5` / `## 7` 一致的 `@`，不得仅保留纯描写。
- **粘贴用正文（代码块内）**：**不写**「全能参考生视频」等产品入口/工作流套话（入口写在 `## 4.5` 或代码块外说明）；块内只保留画面、运镜、台词、音效、`@` 等即梦能用的描述。
- **交付前自检优先**：每次给用户最终视频关键词前，必须先在内部完成自检，再交付正文。自检重点：是否有容易出毛病的动作/道具/空间关系；是否有多余词、重复描述、互相打架的约束；是否有容易诱发 AI 幻觉的词（如红框、龙形气流、双头毛笔、额外入口、第二个主角）；是否已把「不要/不干嘛」改成正向画面语言。用户要求连续故事标准格式时，优先使用 `jimeng-workflows.mdc` Step 4.5 第一优先级「镜头目的 / 分镜首帧画面 / 画面内容」；旧「景别 / 构图 / 运镜手法 / 画面内容」格式保留为第二优先级。

### 对话中交付

- 与落盘文件 **同一顺序、同一镜头编号**；每镜给出 **完整可复制** 的提示词块。
- **禁止**只发文件路径、**禁止**混用「镜头① / 镜头1 / 分镜A」等编号。

## 5. 视频提示词通用硬约束

### 5.1 单段 ≤15 秒 + 真实时间码分配

- 即梦每条视频导出上限为 **15 秒**。
- 当用户要求「把每个镜头切换时长写清楚」时，必须在每条提示词代码块正文中用括号/引号标注清晰时间段，如「`0-5s`……」「`5-9s`……」。
- 时间段必须依据 **台词长度、动作量、口型难度、镜头运动幅度** 做真实分配，**禁止**用平均分段（如统一 `0-4s/4-8s/8-12s`）当作占位。
- 若某段台词过长导致单条 ≤15 秒内口型不稳，优先 **拆成多条即梦分别导出再剪**（台词逐字不改）。

### 5.2 字幕与画面文字默认禁止

每条 Seedance 视频提示词的硬性规则或画质约束里必须写清：

```
禁止生成字幕、禁止生成屏幕文字、禁止生成标题文字、禁止生成水印
```

除非用户当次明确要求画面内出现文字，否则不要让模型生成任何可读文字，字幕统一后期添加。

### 5.2.1 同段风格一致性

同一段 Seedance 视频内，人物、场景、道具、画作/壁画、服装材质必须属于 **同一部片子的同一画风体系**。写关键词时要显式统一为同一画风锚（如“皮克斯式 3D 动画电影风格”），并在素材绑定处说明各 `@图片N` 只用于锁对应维度但最终输出必须同片统一：角色不能像另一套建模，场景不能比人物更写实或更卡通，道具不能变成不同材质体系。若已有参考图风格不一致，提示词必须写清“最终视频统一采用 {目标画风}，各参考图仅锁造型/空间/道具结构”。

### 5.3 人物开口的景别（默认优先，不强制）

出现台词时，**优先**在该句台词对应的时间段把镜头推进到 **面部近景/特写**（如「中景→快速推近到特写」或「切到近景反应镜再开口」），让口型清晰、情绪可读。

- **适合给特写**：长台词、情绪爆发、笑点落在表情/停顿、需要"反应镜"承接的段落。
- **可保中景**：台词很短且动作/空间关系更重要（劈柴、开门走位、掏钱袋等）；但需保证嘴型可见、表情读得出（如中景微推到半身近景），避免全程大全景说完。

### 5.4 用户台词不可改（铁律）

> **总则**：用户在对话、脚本、备注、背景材料、结尾点题、旁白总结等任意位置给出的具体句子，**都属于"用户台词/旁白原话"**，未经用户当次明确授权，**一律不得改动**。

**禁止的具体行为：**

- **缩短**：把「我今天就把这本书看完」简写成「我把书看完」。
- **同义改写**：把「孩子数学突然掉队」改成「孩子数学一下不行了」。
- **换标点 / 换语序**：把「他啊，根本不是笨」改成「他根本不是笨啊」或加去标点。
- **拆句合句**：把一句拆成两句、或把两句并成一句。
- **错别字"修正"**：除非用户明确说允许，否则连用户原文里的错别字、口语化字（"咋""啥""那啥"）都要原样保留。
- **删除**：在视频提示词、四段式、Markdown 落盘版任何位置因"放不下"「太长」「换行不方便」而删去某句。
- **替换数字 / 量词 / 称谓**：用户写「三件不气人」就不能写成「三个不气人」；写「樵夫」就不能写成「砍柴人」。

**唯一允许的处理：**

- **逐字引用** 到提示词正文 / 项目档 / 镜头分段；多段拆分时台词归属哪一段由助手判断，但**字面不动**。
- **拼读纠音**（仅 Seedance 音色提示词层）：如台词里有歧义读音，可在硬性规则里写「按 XX 读音念」，但原台词字面**仍不改**。
- 如确需改动（如台词长度超出单段 ≤15 秒口型上限），必须**先停下来问用户**，拿到当次原话授权后再改；禁止在交付正文里写「若太长可缩短为……」类分支。

**资源参考不成立时的处理**：若 `@视频N` 音色参考不存在或与说话者不匹配，**保留用户原台词**，把"音色严格参考 @视频N"改为「不指定音色参考」或「使用自然清晰旁白音色」之类描述；**删音色参考可以，删用户台词不行**。

**自检（每次交付前）：**

- [ ] 把用户当次给的台词 / 旁白原文逐句对照交付稿，是否**逐字相同**？
- [ ] 是否有为了"画面好排"「时间码好分」而擅自缩词、换词、删句？
- [ ] 若必须改动，是否**当次拿到了用户口头授权**？

## 6. 用户强制唯一视频关键词格式（覆盖条款）

> 适用范围：用户明确要求"以后不管什么剧情都按照这一段关键词格式来""严禁出现其他格式/多余内容"时，本节 **覆盖** 上文对"对话交付外层结构"的要求（但仍必须满足全能参考的 `@图片N/@视频N` 绑定硬约束）。

### 6.1 核心澄清：只统一「格式与要素顺序」，不锁死「画风/风格」

- **格式**：关键词文本的组织方式与要素顺序（时间码、硬切、质量词位置等）。
- **风格/画风**：黑白线稿、超写实、国风、2D 卡通等审美取向。用户要求统一格式时，**不得**把画风也写死；画风应随用户当次需求变化。

### 6.2 唯一标准格式

对话里只交付 **一段可直接粘贴** 的视频关键词（不要额外章节、不要额外解释、不要第二套模板），结构固定如下：

- 第一行固定：`硬性规则：...`（写清所有不可违背约束，如"IP 严禁嘴巴""除 IP 外都是真人长相""必须参考 @图片N"等）
- 仅三段时间轴（示例形态固定）：
  - `[00:00-00:XX] ... 黑白线稿漫画风/超写实... 4K 超高清 ... 硬切至`
  - `[00:XX-00:YY] ... 黑白线稿漫画风/超写实... 4K 超高清 ... 硬切至`
  - `[00:YY-00:ZZ] ... 黑白线稿漫画风/超写实... 4K 超高清 ...`
- 每段必须包含：**景别/运镜 + 主体动作 + 环境要点 + 画风一句（可变）+ 质量词**（如"4K 超高清 画面稳定 动作流畅 细节清晰 无畸变 无模糊 无闪烁 背景稳定"）。
- `@` 规则：正文必须出现所绑定的 `@图片N/@视频N`，且与用户在即梦上传顺序一致（仍遵守"全能参考"路径）。

## 7. 四段式模版（每镜：风格 / 角色 / 场景 / 分镜头）

当用户要求按「网图模版」拆成四小段时遵守：

- **【分镜头】**：沿用本仓库 **一段式视频分镜文风**（与 `## 5` 代码块同类叙述），**不按**「画面 / 动作 / 音效」等再拆条列点。
- **【场景】**：只写本段空间、光色、布景锚点；**禁止**写元说明类套话（如「无单独场景参考图、文字锚点即可」）。
- **【角色】与【分镜头】称谓一致**：【角色】里用什么称呼（如樵夫、女初中生），【分镜头】里指同一人须 **同一套称呼**。
- **`@` 不重复**：【角色】段已写明「（参考@图片N）」时，【分镜头】正文 **不再写 `@`**，用与【角色】一致的人名/身份描写即可。
  - **与硬约束的衔接**：项目内 `## 5`「提示词（整段复制）」代码块 仍须在正文含 `@`，与 `## 4.5` / `## 7` 一致。若当次用户 **只要四段式说明、不要单独代码块**，从其约定。

## 8. 自检（交付前扫一眼）

### 8.1 结构与编号

- [ ] 章节是否按 `## 1`~`## 7`（及按需 `4.5`）排好？
- [ ] 分镜是否全是 `### 镜头NN`（两位数）？
- [ ] 对话里是否也按同结构贴出了复制块？

### 8.2 `@` 与全能参考

- [ ] 视频是否按 **全能参考** 写清上传顺序与 `@`，提示词内是否含 `@图片N`（非仅纯文字）？
- [ ] 用户未声明纯文生时，正文是否含 `@`？
- [ ] 用户声明不要 `@` 时，正文是否已清空所有 `@`？
- [ ] 道具 `@` 是否仅在用户明确要求时才出现？

### 8.3 Seedream 出图

- [ ] 角色是否只准备 **一张** **16:9** **三视图总览**（除非用户另要其它）？
- [ ] 道具 / 场景图是否未经用户要求就新增了 Seedream 出图块？（若未要求则不应有）
- [ ] 用户已自备场景图时，是否改为上传 + `@`，而非再生成场景 Seedream？

### 8.4 视频通用硬约束

- [ ] 是否写了 **禁止生成字幕 / 屏幕文字 / 标题文字 / 水印**（除非用户明确要求画面内文字）？
- [ ] 每段时间码是否按 **真实需要** 分配（非平均三等分占位）？
- [ ] 单段是否 ≤15 秒？超长成片是否拆条？
- [ ] **真人口播 / 超写实实拍真人**：硬性规则里是否完整写了 `角色说话时音色严格参考@视频1（语气由提示词关键词控制），禁止生成别的音色`？

### 8.5 粘贴用正文

- [ ] 每镜是否都有 **单独一块** 可粘贴即梦的完整正文，且 **无**「全能参考生视频」等冗余套话？

### 8.6 五维度诊断与做减法

- [ ] 用户提供了 `@素材` 时，是否先做了**五维度诊断**（扫描素材已锁定哪些维度），并向用户简述诊断结果？
- [ ] 素材已锁定的维度（如人物外貌、场景环境、画风），提示词里是否**已省略冗余重复描写**，而非七要素全堆？
- [ ] 基调是否只写**参考图用途、最终画风、必要硬性规则**，而没有二次描述参考图已锁定的外貌、道具、场景细节？例如已有角色三视图时，基调只写「严格参考@图片1保持角色一致」，不要再复述发型、服装、五官；已有场景图时，基调只写「严格参考@图片2保持场景空间和光影一致」，不要再复述亭子、树木、门、靶墙等细节，除非用户明确要求修正某个参考图维度。
- [ ] 凡参考图里已经体现角色样貌、服装、道具或行为姿态，视频提示词是否**没有复述**这些已锁信息？若使用俯视点位图，基调是否只写「@图片N 是点位示意图 / 用于锁点位编号」，点位解释是否只放在对应分镜里？
- [ ] 基调是否避免推进剧情？剧情动作、位置变化、表情变化、道具放置等应写在对应分镜的「画面内容 / 运镜手法」里；基调只建立全局风格、素材绑定和不可违背的硬规则。
- [ ] 任意分镜图（六宫格/九宫格/其它数量）是否内部统一使用「九宫格分镜模板」字段，但关键词正文不出现「九宫格分镜模板，实际排版为……」这类元说明？
- [ ] 分镜图数量和每张格数是否先根据视频实际需要的**切镜数量**规划，而不是随手凑格子？
- [ ] 每一格是否都有明确叙事功能（交代新信息、推进动作、承接反应、制造转折或收束结果），没有无功能重复画面？
- [ ] 后续镜头出现的新道具（绳子/锤子/袋子等）是否已有前置分镜交代？若没有，是否改成徒手动作或补充拿道具分镜？
- [ ] 分镜图画幅是否写的是**单张分镜图/每格画幅**，例如「每格为 16:9 横版构图」？
- [ ] 分镜图提示词是否用自然画面语言写清**观众在屏幕里实际看到什么**，而不是堆「景别、镜头角度、焦段、景深」等术语标签？
- [ ] 画面陷阱是否按**观众实际看到的前中远景关系**写清：谁靠近镜头、谁远离镜头、人物正脸/侧脸/背影、门框/钟/桌椅等空间锚点分别在哪一层，而不是只写抽象朝向？
- [ ] 多人物 / 人物与关键道具同框时，构图是否先按**屏幕可见关系**锁住位置：谁在前景 / 中景 / 远景，谁靠近镜头 / 远离镜头，谁在画面左侧 / 中央 / 右侧，谁面向镜头 / 侧对镜头 / 背对镜头，视线目标在哪里？禁止只写「左后方、旁边、远处、侧边」这类抽象方位。优先写成用户能直接看懂的画面句：如「老翁在画面左下前景，离镜头最近，身体显得更大；陈尧咨在画面中右中景，离镜头更远，身体显得更小，侧身面向远处靶墙；靶墙在画面远景中央」。朝向也必须单独锁：如「陈尧咨身体侧面对镜头，脸和胸口朝向远处靶墙；老翁脸和胸口朝向画面中间庭院，视线看向陈尧咨和靶墙」。参照系说明只能作为补充，不能代替屏幕可见关系。
- [ ] 易错格是否使用 image 能直接画的屏幕坐标词（靠近镜头/远离镜头/画面中央/右偏上/占大部分视角/占小部分视角/背对镜头），而不是只写「必须清楚表现」？
- [ ] 人物与关键道具需要拉开距离时，是否明确写了「距离很远 / 中间隔着宽阔空地 / 人物只占画面小一角」等可画距离关系？
- [ ] 涉及**人物与道具互动**时，是否在「画面内容」里把动作先后顺序和方位顺序写死？必须写清先做什么、再做什么、从哪只手 / 哪个方向开始、道具如何移动、最终停在哪里。例如放油担：先停步稳住身体 → 双手握住扁担两端 → 肩膀微微下沉 → 先把左侧油桶降到地面 → 再把右侧油桶降到地面 → 扁担横放在脚边；射箭：先抬弓 → 搭箭 → 拉满弦 → 瞄准 → 松弦 → 箭离弦 → 收弓。构图不写这些过程，只在画面内容中按时间顺序写。
- [ ] 若用户要求「让 image 自己发挥 / 只写每格剧情」，是否已退回逐格剧情提示，避免过度指定位置关系和摄影术语？
- [ ] 几乎永远需要文字写的维度（运镜、时间轴动作）是否只写进**视频关键词**，没有写进分镜图提示词？
- [ ] 用户要求「生成连续故事视频关键词」时，是否调用 `jimeng-workflows.mdc` Step 4.5 第一优先级新模板（基调 + 分镜时间 + 镜头目的 + 分镜首帧画面 + 画面内容）？旧四字段模板是否仅作为第二优先级使用？
- [ ] 连续视频后续段是否在**开头基调**写明「本段延续@视频1的内容，参考@视频1最后一帧画面作为本视频开头画面」？
- [ ] 连续视频后续段的分镜一「分镜首帧画面」是否只写「参考@视频1最后一帧画面作为本镜头首帧」，不复述上一帧细节、不新增构图元素？
- [ ] 连续视频后续段的分镜一是否把重点放在「画面内容」：镜头如何从上一帧继续、故事如何发展？
- [ ] 若 `@视频1` 只用于状态参考，是否只写正向用途「@视频1用于参考上一段故事状态：...」，避免写「不参考最后一帧/不承接最后一帧」否定句？
- [ ] 若开头已写清 00:00-00:02 的承接动作，是否避免把这段重复写成分镜一，而是直接从新剧情分镜继续？
- [ ] 视频关键词里的「分镜首帧画面」是否只写**第一帧静态定格图**：负责安排景别/机位、起始人物、道具、场景、空间层级、朝向、视线和初始动作状态；严禁把走来、放下、射出、转头、抬手、随后、然后、结果、推近、淡出、回到等运动过程写进去。
- [ ] 连续故事视频关键词是否按第一优先级三字段归位：镜头目的只写本镜功能；分镜首帧画面只写第一帧已看见的东西；画面内容写镜头运动、动作链、动态位置/朝向/距离关系、表情变化和结束状态？
- [ ] 画面内容是否继续锁住动态关系，而不是只在首帧锁位置？例如谁从哪侧伸手、道具离嘴/手/球门多远、人物动作后落在谁前方或身后。
- [ ] 若使用第二优先级旧四字段，是否完成四字段归位自检：景别无构图词，构图无过程词，运镜无剧情结果，画面内容不大段重复构图？
- [ ] 连续故事视频关键词是否避免「可以 / 或 / 或者 / 可选 / 如有 / 若」等分支词，改为唯一确定的首帧、动作、道具和镜头运动？
- [ ] 参考素材是否足够清晰（≥2K / 1024px 以上）？模糊素材是否已提醒用户先做超分处理？

### 8.7 关键词联想陷阱

- [ ] 提示词中是否存在**否定词**（不要、禁止、没有）？如有，是否已改写为**正向替代**？
- [ ] 视频关键词的「构图」和「画面内容」是否优先只写**要生成什么、怎么动、停在哪里**，而不是写「不要/不干嘛」？除硬性禁令（字幕、屏幕文字、水印等）外，构图和画面内容里的否定句要改成正向执行句，例如把「不要完全飞出墙面」改成「龙仍保持墙上壁画状态，墨线和云气在墙面周围震动翻涌」。
- [ ] **分镜正文是否避免反向约束词**：除开头「基调 / 硬性规则」可集中写必要禁令外，后续每个分镜的「构图 / 运镜手法 / 画面内容」尽量不要再写「禁止 / 不要 / 没有 / 不出现 / 不转弯 / 不反向」等反向词；这些词位置靠后时权重低且容易反向触发幻觉。分镜里改用正向执行句锁画面，例如把「不出现第二支箭、不反向飞」改成「本段只射出一支新箭，箭头始终朝屏幕左侧，箭从屏幕右侧直线飞向屏幕左侧，射完收弓」。
- [ ] 是否存在可能触发**刻板联想**的职业/场景名词（如"游戏""护士""厨师"等）？如有，是否已改为外观描述？
- [ ] 涉及人物朝向时，是否用了**空间锚点**（讲台、黑板、桌椅等具体物件做参照系）而非抽象方向词？

### 8.8 多人物空间关系铁律（图片 / 视频通用）

- [ ] **先锁核心物理关系，再写氛围**：涉及人物、道具、场景互动时，必须先写清谁在前景/中景/远景、谁靠近镜头/远离镜头、谁正对镜头/背朝镜头/侧面对镜头、谁的脸和胸口朝向谁，再写光影、情绪、特效。
- [ ] **核心关系必须符合剧情常识**：如“殿上王与阶下乐师”必须写成「齐宣王在高台王座上，脸和胸口朝向阶下乐师；阶下乐师在低处席位上，脸和胸口朝向齐宣王」。不得只写“王在远景、乐师在前景”而漏掉双方正面对坐/面对奏乐关系。
- [ ] **禁止给模型选择题**：朝向、站位、队形、动作不得写「或 / 可 / 可以 / 也许 / 侧背对」等分支词；必须给唯一确定方案。例如“所有乐师的脸和胸口都朝向远景王座，后脑勺和肩背朝向镜头”。
- [ ] **队列必须写运动方向**：队伍场景写清「队伍从画面近景下方沿台阶走向远景宫门」，并写清等待者、通过者、发放者各自站在哪一侧，避免队伍反向、散开或互相穿插。
- [ ] **交互动作按顺序拆开**：涉及递物、接物、放行、行礼时，画面内容必须写清动作链：谁先做什么 → 谁把什么递给谁 → 对方用哪只手/双手接住 → 物品最终停在哪里。不得让 AI 自行推断多人交互。
- [ ] **多人减少交互复杂度**：同一镜头多人时，优先只保留一个主交互，其余人作为等待/围观/背景队列；人物服饰可写“服装类似、长相各异”，不要为多人各写复杂服饰细节导致模型分心。
